An application engineer working on infrastructure

I spent years writing the React, Node and Go code that runs on servers. That's why I start infrastructure work by asking what the application needs.

Terraform is the source of truth

Every environment I build can be destroyed and recreated from code. When an AWS account ran out of credit mid-project, I rebuilt the whole stack on a new account from the same Terraform.

Least privilege by default

GitHub Actions authenticates with OIDC instead of stored keys. Each Kubernetes service gets its own IAM role through IRSA, and developers get read-only, namespace-scoped access.

Cloud spend is part of the design

I write pause and resume automation for expensive environments and tear them down cleanly when the work is done, including the dependency and state issues that teardown uncovers.

Things that broke, and how I fixed them

Most of the learning happened when something failed. These are real issues from the projects above, written up the way I'd write a short incident note.

EKS node group would not come upProject Bedrock, NodeCreationFailure

Symptom

The cluster was created, but worker nodes never joined and the node group failed.

Cause

The node subnets had no route table association and public IP assignment was off, so nodes couldn't reach the control plane to bootstrap.

Fix

Corrected the subnet routing and IP settings in Terraform. The lesson: a Kubernetes failure can start at the VPC layer.

Pods couldn't reach instance metadataStartTech, EKS pod networking

Symptom

Workloads on the nodes failed when they tried to fetch AWS credentials from the metadata service.

Cause

The default IMDSv2 hop limit of 1 drops responses that have to travel one extra network hop into a container.

Fix

Added a custom launch template in Terraform that raises the hop limit for the node group.

Every CI run said resources "already exist"StartTech, Terraform state

Symptom

Pipeline applies failed repeatedly, and parallel runs left orphaned AWS resources behind.

Cause

No remote backend was configured, so each runner started with empty state and tried to create everything again.

Fix

Moved state to an S3 backend with locking, and wrote an idempotent Bash script to clean up the orphans.

Users were logged out with a 401 on every requestStartTech, Go backend behind HTTPS

Symptom

Login succeeded, but the next API call through CloudFront was rejected.

Cause

Viper's AutomaticEnv() wasn't picking up nested settings, so the cookie domain and secure flag never applied in production.

Fix

Added explicit BindEnv() calls and set COOKIE_DOMAINS and SECURE_COOKIE correctly for HTTPS.

Backend couldn't connect to RedisStartTech, ElastiCache

Symptom

Pods started, but readiness checks failed and cache calls timed out.

Cause

The endpoint passed into the app had no port, and the probe timeouts were too aggressive for startup.

Fix

Added the port to the endpoint configuration and relaxed the liveness and readiness probe timings.

Terraform destroy got stuck halfwayProject Bedrock, teardown

Symptom

Destroy failed on secretstores.external-secrets.io, then on a non-empty S3 bucket.

Cause

The External Secrets CRDs were removed before Terraform deleted the objects that depended on them.

Fix

Temporarily disabled the dependent config, removed stale entries from state, emptied the bucket, and finished with a clean destroy.
